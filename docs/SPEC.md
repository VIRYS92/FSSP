# SPEC: контроль постановлений ФССП

Статус: согласованный источник требований; подготовительный этап завершён, PDF-импорт реализован поэтапно.

## Цель и границы

Веб-приложение для сотрудников управляющей компании: контроль постановлений ФССП об обращении взыскания на доходы должников, отправлений работодателям, доставки, исполнения и поступлений. Главный поток — импорт постановлений из PDF, автоматическое извлечение, проверка сотрудником и работа с подтверждённой записью в реестре.

Целевая база — PostgreSQL. Целевое размещение — существующий AdminVPS. Денежные значения хранятся как `NUMERIC(18,2)`/`DECIMAL(18,2)`, передаются API десятичными строками и не рассчитываются через `Number`.

Excel используется только как источник структуры и бизнес-логики. Пользовательский импорт XLSX/XLSM, сопоставление колонок и синхронизация с книгой не нужны. Экспорт — обычный оформленный XLSX без макросов, для руководства и печати.

Новое приложение должно запускаться с чистой БД без рабочих данных из образца. Реальные записи из образца не переносятся автоматически; решение об однократном переносе принимается отдельно.

## Процесс работы над проектом

Работа идёт небольшими этапами. За один запрос выполняется только следующий незавершённый этап. После каждого этапа фиксируются проверки и состояние в `docs/PROGRESS.md`. После детального анализа документов и после проектирования архитектуры/БД требуется отдельное согласование. До согласования запрещены реализация следующих этапов, публикация, `git push`, изменения AdminVPS, удаление рабочих данных и разрушительные миграции.

## Основные сущности и связи

- Одно постановление — одному должнику и одному работодателю; у должника может быть несколько постановлений.
- Один номер ИП может иметь постановления разным работодателям.
- Один конверт содержит несколько постановлений; повторная отправка создаёт новый конверт.
- Связи строятся по постоянным ID, не по строкам Excel и не только по ФИО.
- Работодатель из справочника и реквизиты работодателя в конкретном постановлении не должны незаметно переписывать друг друга.
- Неполное постановление можно сохранить с явной отметкой уточнения, без фиктивного работодателя или ложной связи.

Предварительный набор таблиц: `users`, `user_sessions`, `debtors`, `employers`, `enforcement_proceedings`, `orders`, `order_field_reviews`, `shipments`, `shipment_items`, `order_shipment_preferences`, `payment_transfers`, `payment_events`, `actions`, `documents`, таблицы связей документов, `import_batches`, `import_batch_files`, `import_items`, `control_settings`, `audit_log`, `document_chunks`; векторный слой — только после отдельного согласования.

Технические правила: UUID для внутренних ключей; пользовательские ID, ИНН, номера ИП, лицевые счета и трек-номера — `TEXT`; даты — `DATE`; моменты событий — `TIMESTAMPTZ`; распознавание, исправления и предупреждения — `JSONB`; внешние ключи и ограничения допустимых значений; архивирование вместо удаления связанных данных; авторы и временные метки; версия записи для конфликтов редактирования.

Постоянные коды (например, `П-0001`, `К-0001`, `С-0001`) выдаются последовательностью PostgreSQL или эквивалентным безопасным механизмом, не через `MAX(id)+1`. Коды не меняются, не переиспользуются и не обрезаются после 9999; пропуски после отменённых операций допустимы. Восстановление не уменьшает верхнюю границу.

## PDF-импорт

Поддержать один PDF, несколько файлов и общий пакет. Поток: загрузка → извлечение текста → определение границ документов → извлечение полей → проверки → редактируемый предпросмотр → подтверждение → сохранение. До подтверждения рабочий реестр не изменяется; исходное распознавание и ручные исправления хранятся отдельно.

Извлекать при наличии: ФИО и дату рождения должника, адрес должника, номер и дату возбуждения ИП, вид/номер/дату исполнительного документа, выдавший орган, номер судебного дела, номер/дату постановления, идентификатор документа ФССП, работодателя и адрес, отдел ФССП, пристава, правильно принадлежащие контакты и процент удержания.

Должник определяется по контексту конкретного постановления, а не по первому имени и не по перечню солидарных должников. Работодатель ищется в блоках «место работы должника», пунктах 2 и 6; расхождения показываются. Адрес должника, адрес взыскателя и адрес помещения УК не подменяют адрес работодателя. ИНН работодателя при PDF-импорте оставляется пустым для ручного ввода; ИНН других участников не сохраняется.

Предпросмотр показывает поля рядом с файлом и страницами, пропуски, неоднозначности, ошибки, возможные дубли, источник и итог выбранных действий; отдельный документ не скрывает результаты остальных. Продолжения, уведомления и приложения не создают лишних записей. Границы нельзя определять только фиксированным числом страниц. При нечитаемом тексте сообщается проблема и доступен ручной ввод/прикрепление PDF. OCR — отдельный этап после реализации и проверки базового извлечения; внешние AI/OCR-сервисы не используются без согласования.

Повторный импорт сверяется прежде всего по идентификатору документа ФССП, затем по комбинации реквизитов. Один номер ИП не является достаточным признаком дубля. Нельзя автоматически объединять записи из-за неизвестного работодателя, перезаписывать записи без подтверждения или терять ручные исправления. После изменений в предпросмотре проверки дублей выполняются повторно. Импорт не создаёт фактов отправки, вручения, исполнения или поступления денег.

Для значимых реквизитов различаются состояния «не найдено», «возможно неполно», «не удалось прочитать», «требует проверки» и «проверено сотрудником». Неполные реквизиты не блокируют сохранение, но отправка без проверенного получателя и адреса запрещена; отсутствие ИНН само по себе отправку не блокирует.

## Реестр и интерфейс

Основной реестр показывает ID, должника, работодателя, доставку, исполнение, поступления УК, следующий контроль, состояние и ответственного. В карточке — постановление, работодатель, отправления, поступления, контроль, документы и история. Навигация: «Обзор», «Постановления», «Отправления», «Поступления», «Настройки»; интерфейс на русском.

Нужны серверные фильтрация и пагинация, сортировка, закреплённые заголовки, выбор столбцов, поиск по ID/ФИО/работодателю/ИНН/ИП/трек-номеру, фильтры ответственного, доставки, исполнения, контроля и неполных реквизитов. Рассчитывать на сотни постановлений и тысячи событий. Отдельно показывать неполные реквизиты работодателя.

## Отправления

Поток: выбрать постановления → проверить получателя и адрес → создать черновик конверта → зафиксировать отправку с датой, трек-номером и документами → обновлять доставку. Предупреждать о разных работодателях и неполучателях; запрещать повторную пару «конверт—постановление».

После отправки получатель, адрес и состав фиксируются. Изменение работодателя не переписывает прошлые конверты; для повторной отправки создаётся новый. Сохраняются статусы, даты отправки/проверки/вручения/возврата, причина возврата и вид отправления. Актуальный конверт определяется единой логикой; при одинаковом времени показывается неоднозначность и разрешается ручной выбор только среди конвертов с этим постановлением.

## Поступления и контроль

Этапы «Депозит ФССП» и «Счёт УК» хранятся раздельно; один перевод может иметь оба события, но они не складываются в общий приход. В итоги попадают только корректная связь, источник «Этот работодатель», подтверждение «Подтверждено» и отсутствие блокирующих ошибок номера ИП. Спорные события сохраняются для уточнения; неизвестные ID остаются исходным текстом. Отсутствие событий не означает доказанное отсутствие платежей; остаток задолженности не вычисляется.

Поля платежа: сумма, дата, период удержания, платёжный документ, связь перевода, подтверждающий файл и примечание. Нужны предупреждения о возможных дублях без чрезмерного уникального запрета.

Следующий контроль рассчитывается по отправке, вручению, проверке исполнения и подтверждённому поступлению УК. Сохраняются интервалы, ручная дата с согласованным приоритетом, действие, исполнитель, срок, состояние, результат и время выполнения. Состояния: «Просрочено», «Сегодня», «Скоро», «Запланировано», «Назначить действие», «Назначить ответственного», «Завершена». Интервалы — внутренний график УК в календарных днях. Часовой пояс по умолчанию — `Asia/Yekaterinburg`, с настройкой; расчёт «сегодня» должен быть единым. Завершение/архив прекращают напоминания, но сохраняют историю и связи.

## Обзор и экспорт

Обзор показывает активные записи, просроченный контроль, задачи на сегодня/ближайшие дни, вручённые постановления без исполнения, платежи к уточнению, неполные реквизиты и раздельные итоги ФССП/УК. Расчёты интерфейса и экспорта едины, повторяющиеся связи предварительно агрегируются.

Нужны представления/запросы для основного реестра, неполных реквизитов, просроченных задач, ответственных, подтверждённых поступлений по месяцам, исключённых событий с причинами, актуальных отправлений и обзорных показателей. Архивные данные не должны исчезать из исторических отчётов без явно выбранного фильтра.

Экспорт — обычный XLSX без макросов: весь реестр, все записи текущих фильтров независимо от страницы или выбранные записи; сохраняется сортировка и выбор столбцов. По умолчанию: номер, ID, должник, лицевой счёт, работодатель, ИП, номер/дата постановления, отправка, доставка/вручение, исполнение, подтверждённые поступления УК, контроль, состояние, ответственный. Дополнительно — ИНН/адрес работодателя, ФССП, примечания, неполнота и неоднозначности.

Файл содержит название, дату/время и часовой пояс, описание выборки, количество, сводку и раздельные финансовые итоги. ID/ИНН/лицевые счета/ИП/трек-номера — текст; суммы — числа с денежным форматом; даты — `ДД.ММ.ГГГГ`; неизвестные значения — пусто или понятная отметка, не ложный ноль. Оформление рассчитано на A4, альбомный реестр, повтор шапки, фильтр, печать по ширине и чёрно-белую читаемость. Экспорт не является резервной копией и не служит обратным импортом.

## Права, документы и размещение

Закрытый доступ сотрудников; матрица `admin/editor/viewer` согласуется отдельно. Права проверяются на сервере для просмотра/изменения, импорта, экспорта, документов, настроек, сотрудников, резервных копий и восстановления. Пароли — только хеши; секреты не попадают в Git; прямой URL к чужому документу должен быть закрыт. PDF и документы хранятся в постоянном хранилище, не во временном контейнере. Аудит фиксирует кто/когда/что изменил и старые/новые значения; изменение и аудит по возможности одной транзакцией. Персональный текст PDF не пишется в обычные логи.

Подготовить Dockerfile, Compose, PostgreSQL, reverse proxy/HTTPS, постоянные тома, миграции, health-check, безопасный `.env.example`, инструкции запуска/обновления/отката и резервного копирования БД, документов и настроек. PostgreSQL не публикуется в интернет без необходимости; версии зависимостей и образов фиксируются. Перед AdminVPS нужно проверить ОС, ресурсы, домен, доступ, занятые порты, сервисы и существующие копии; не считать VPS пустым и не выполнять развёртывание без доступа/согласования.

## Приёмка

Приёмка должна включать чистый запуск/миграции, ручные записи, постоянные ID и конкуренцию, PDF одного/нескольких/пакета, границы и продолжения, правильного должника, пропуски/обрезки/нечитаемые реквизиты, ручные исправления и повторный импорт, отправления и доставки, раздельные платежи, точные деньги, контроль/таймзоны, права/файлы/конфликты, резервное копирование/восстановление, поиск, работу без векторного слоя, запуск из чистого GitHub и готовность к AdminVPS. Для XLSX — все режимы, фильтры, выборки, итоги, типы, открытие и печать. Сначала целевые автоматические тесты, затем интеграционная и браузерная проверка; невыполненные проверки и ограничения перечисляются отдельно.
