# Правила работы с проектом

- Работать по этапам из `docs/PLAN.md`; за один запрос выполнять только один следующий незавершённый этап.
- После каждого этапа запускать относящиеся к нему проверки, обновлять `docs/PLAN.md` и `docs/PROGRESS.md`, кратко отчитываться и останавливаться.
- До отдельного согласования не реализовывать следующие этапы после подготовки, не выполнять `git push`, публикацию, изменения на AdminVPS, удаление рабочих данных и разрушительные миграции.
- Не переносить рабочие записи из `REESTR.xlsm` автоматически. Книгу использовать только как источник структуры и бизнес-правил; пользовательский импорт Excel не создавать.
- Не фиксировать секреты, реальные PDF, рабочую БД и резервные копии в репозитории.
- Считать `docs/SPEC.md` источником согласованных требований, а `docs/PROGRESS.md` — источником текущего состояния и следующего шага.
