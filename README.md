# Контроль постановлений ФССП

Проект содержит каркас, схему, доступ, PDF-импорт, рабочий реестр постановлений, отправления, поступления и контроль. Репозиторий запускает API, PostgreSQL, авторизацию, роли, защищённое хранилище документов, пакетный предпросмотр и подтверждение PDF, ручное создание и редактирование постановлений, поиск по фрагменту или полнотекстовый поиск, конверты, раздельные события ФССП и УК, а также контрольные действия со сроками 7/30/30.

## Локальный запуск

Требуется Node.js 24.19.0+ и npm (пакет совместим с Node.js 22.13+).

```bash
npm ci
npm run build
NODE_ENV=production DB_REQUIRED=false npm start
```

Проверки:

```bash
curl http://127.0.0.1:3000/healthz
curl http://127.0.0.1:3000/readyz
```

Для применения пустой PostgreSQL-схемы задайте `DATABASE_URL` и выполните:

```bash
npm run db:migrate
```

Миграции версионируются в `migrations/` и проверяют SHA-256 уже применённых файлов. Изменение применённой миграции завершится ошибкой; новые изменения добавляются новым файлом.

## Авторизация и документы

Первого администратора можно создать один раз через `POST /api/auth/bootstrap`, только если `ALLOW_BOOTSTRAP=true` и таблица пользователей пуста. **Сразу после создания первого администратора обязательно установите `ALLOW_BOOTSTRAP=false` и перезапустите приложение.** Пароли хешируются Argon2id, сессия хранится в БД и передаётся только в HttpOnly-cookie.

Документ загружается авторизованным `admin` или `editor` бинарным `POST /api/documents` с заголовками `X-File-Name` и `X-File-Type`. Файлы хранятся вне `public`, выдаются только через авторизованный endpoint и регистрируются в аудите.

PDF-предпросмотр выполняется через `POST /api/imports/preview` для `admin/editor`. Он извлекает текстовый слой без OCR, сохраняет исходный PDF и черновик предпросмотра, показывает предупреждения и не создаёт рабочую запись. Ручные наименование, ИНН и адрес работодателя сохраняются через `PATCH /api/imports/items/:id`; пакет подтверждается отдельным commit-endpoint.

Пакет PDF загружается как multipart-запрос `POST /api/imports/package-preview` с несколькими полями `pdfs`. Состав пакета и причина ошибки каждого файла видны до сохранения. Повреждённый файл можно явно исключить через `POST /api/imports/items/:id/exclude` с причиной. Для подтверждения остальных используется `POST /api/imports/:id/commit` с JSON `{ "confirm": true }`. Возможный дубль возвращает конфликт и требует отдельного `"allowDuplicates": true`; файл с ошибкой нельзя пропустить молча: до явного исключения он блокирует commit.

## Рабочий реестр постановлений

Реестр доступен всем авторизованным пользователям через таблицу и карточку. Сервер поддерживает поиск по фрагменту (по умолчанию) и PostgreSQL полнотекстовый поиск (`mode=fulltext`), фильтры статуса/ответственного/неполных реквизитов, сортировку и пагинацию; набор видимых столбцов сохраняется в браузере. `admin` и `editor` могут вручную создавать и редактировать записи, назначать ответственного и архивировать постановления. `viewer` имеет доступ только к просмотру.

Наименование, ИНН и адрес работодателя заполняются вручную. Пустые или непроверенные реквизиты помечаются предупреждением и попадают в фильтр неполных записей. Каждое изменение записывается в аудит. Для защиты от незаметной перезаписи PATCH требует текущую `version`; конфликт при одновременном редактировании возвращает `409`, а запись не изменяется.

## Почтовые отправления

Раздел отправлений позволяет создать черновик конверта, выбрать несколько постановлений, проверить получателя и адрес, назначить ответственного, указать тип отправления и трек-номер, зафиксировать отправку, вручение или возврат. При разных работодателях, непроверенных реквизитах, пустом составе или несовпадении получателя показываются предупреждения; финальная отправка блокируется до исправления.

После фиксации отправки получатель, адрес и состав защищены сервером и PostgreSQL-триггером. Повторная отправка создаёт новый конверт, а одна пара «конверт—постановление» внутри состава уникальна. Если несколько отправлений имеют одинаковую дату, API показывает неоднозначность и позволяет `admin/editor` вручную выбрать актуальный конверт.

Для разработки интерфейса и API используйте два терминала:

```bash
npm run dev:api
npm run dev:web
```

Vite будет доступен на `http://127.0.0.1:5173`, API — на `http://127.0.0.1:3000`.

## Поступления

Раздел поступлений хранит отдельные события «Депозит ФССП» и «Счёт УК». Один перевод можно связать с обоими событиями. Для события сохраняются постановление или неизвестный внешний ID, сумма десятичной строкой, дата, период, источник, платёжный документ, примечание и подтверждающие файлы.

В итог попадают только подтверждённые и сверенные события с источником «Этот работодатель», известным постановлением и номером ИП. Возможные дубли показываются отдельно; подтверждение дубля требует явного решения, а итоговая агрегация не удваивает одну комбинацию события. `admin/editor` могут создавать и редактировать записи, `viewer` — только просматривать.

## Обзор и XLSX-отчёты

Раздел «Отчёты» показывает количество постановлений, неполные реквизиты, состояния контроля, вручённые постановления без подтверждённого платежа УК и раздельные суммы ФССП/УК. `GET /api/reports/overview` принимает те же фильтры и режим поиска, что и реестр.

`GET /api/reports/orders.xlsx` формирует обычный XLSX без макросов. Экспорт включает всю выборку по фильтрам, а не только текущую страницу; параметр `ids` ограничивает файл выбранными постановлениями, `columns` сохраняет выбранные столбцы, `sort` и `direction` сохраняют сортировку. Файл содержит листы «Сводка» и «Реестр», фильтр, закреплённую шапку, печать A4 в альбомной ориентации, даты `ДД.ММ.ГГГГ`, текстовые ID/ИНН/номера ИП и денежный формат с двумя знаками. Excel-импорт не выполняется.

## Поиск и hardening

Поиск по фрагменту безопасен по умолчанию и ограничен 200 символами. Полнотекстовый режим использует `to_tsvector('simple')` и `websearch_to_tsquery('simple')`; параметры запроса передаются отдельно от SQL. Векторный поиск для базовой работы не требуется и не включён.

API добавляет защитные HTTP-заголовки, а ответы `/api/*` помечаются `Cache-Control: no-store`. Перед выпуском проверяйте `npm run typecheck`, `npm test`, `npm run build`, `npm audit --omit=dev --audit-level=high` и `docker compose config --quiet`.

## Docker Compose

Скопируйте `.env.example` в `.env`, задайте непредсказуемый пароль PostgreSQL и запустите:

```bash
docker compose up --build
```

Compose сначала поднимает PostgreSQL, затем однократно выполняет сервис `migrate`, после чего запускает API и no-op worker. Для `app` настроен health-check `/healthz`; PostgreSQL, API и worker перезапускаются после сбоя.

Приложение слушает только loopback-порт `3000`. PostgreSQL наружу не публикуется. Том `postgres_data` хранит БД, `documents_data` зарезервирован для документов. В production reverse proxy и HTTPS должны быть настроены на AdminVPS после проверки занятых портов.

Инструкция deployment, HTTPS, обновления, отката и проверки AdminVPS находится в [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). Скрипты [ops/backup.sh](ops/backup.sh) и [ops/restore.sh](ops/restore.sh) сохраняют и восстанавливают БД с документами; перед восстановлением требуется явное `CONFIRM_RESTORE=YES`.

Фактическое подключение к AdminVPS, настройка DNS/HTTPS и контрольное восстановление на нём ещё не выполнялись: для этого нужны параметры VPS, домен и доступ владельца. Текущая рабочая версия также ещё не опубликована в GitHub: изменения остаются локальными до отдельного решения о commit/push.

## Ограничения текущего этапа

- Пользовательского Excel-импорта нет.
- Excel-импорт не реализован; XLSX-экспорт предназначен для отчётов и не является обратным импортом или резервной копией. PDF-импорт, реестр, отправления, поступления, контроль и отчёты работают без OCR и векторного поиска.
- PostgreSQL-схема и миграция пустой базы уже описаны; они не добавляют рабочих записей.
- `worker` пока является безопасным no-op процессом; фоновые задачи добавляются отдельным этапом.
- Реальные данные из `REESTR.xlsm` не добавляются.
