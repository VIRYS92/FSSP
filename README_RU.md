# Контроль постановлений УК

Рабочее приложение на React 19 / Vinext, TypeScript, Cloudflare Workers, D1 (SQLite) и R2. Интерфейс на русском языке. Авторизация размещённой версии — через вход ChatGPT и серверный список сотрудников.

## Запуск

На этом компьютере зависимости уже установлены: дважды нажмите `Запустить.cmd`. Для распакованного архива этот файл сначала выполнит `npm ci`. Требуется установленный Node.js 22.13+ с npm в PATH. Окно сервера оставьте открытым.

Требуется Node.js 22.13+ и npm. В папке проекта:

```powershell
npm ci
npm run build
node scripts/start-local.mjs
```

Скрипт запуска создаёт недостающие таблицы и индексы. Повторный запуск сохраняет записи и счётчики, в том числе после прерванного создания базы. Если старая версия сообщила `table actions already exists`, используйте обновлённый скрипт; не удаляйте `.wrangler/state`. Откройте адрес, который напечатает сервер (обычно http://127.0.0.1:5173). Локальный вход `/signin-with-chatgpt?return_to=/` использует тестовую личность `seedy@sites.test`; он работает только в режиме разработки на loopback и исключён из production-сборки. Не открывайте dev-сервер в общую сеть.

Первый сотрудник, вошедший в **закрытый** размещённый сайт, становится администратором. Остальным сотрудникам нужны разрешение политики доступа сайта и запись с их email в «Настройки → Сотрудники». Роли: администратор, редактор, чтение. Не меняйте сайт на публичный до настройки доступа.

При первоначальной инициализации переносится единственная заполненная строка исходной книги: **П-0003, ппппп**, счётчик 3. Новые постановления начинаются с П-0004. Это исходная запись, не демонстрационные данные. Пустые строки книги не загружаются.

## Ежедневная работа

1. На «Обзоре» откройте задачи на сегодня, просроченные и записи для уточнения.
2. Создайте постановление. Остальные поля доступны в карточке и форме редактирования. ID выдаётся автоматически, не меняется и не используется повторно.
3. Выберите несколько постановлений в реестре и нажмите «Создать конверт», либо создайте отправление из карточки. Проверьте получателя и адрес. После первой отправки они и состав фиксируются.
4. В карточке конверта меняйте статус доставки и даты. Доставка и вручение обновляются в реестре. Для повторного направления создавайте новый конверт. При одинаковом времени последней отправки выберите конверт вручную в карточке постановления, раздел «Отправления и деньги».
5. Создайте платёжное событие. Данные должника подставляются по ID. ФССП и УК учитываются отдельно; события с неизвестным источником, ошибкой ИП или без подтверждения остаются видимыми, но не входят в итоги.
6. Назначьте действие, ответственного и при необходимости ручную дату. Записывайте результаты работы в историю. Статус «Завершена» и архив прекращают напоминания по постановлению.

Поиск, фильтры, сортировка, пагинация (25 строк) и выбор столбцов работают по загруженным серверным данным. Выбор столбцов хранится только как предпочтение браузера; рабочие данные — на сервере.

## Импорт и экспорт

Импорт `.xlsx` и `.xlsm` доступен администратору. Сначала показываются количество записей, сопоставление заголовков, ошибки, предупреждения и конфликты. Для каждого конфликта выберите сохранение данных приложения или замену данными файла. Настройки из файла применяются отдельно. Неразрешённые ошибки связей блокируют сохранение; некорректные платёжные события могут быть сохранены для уточнения.

Импорт не запускает VBA и не доверяет вычисленным итогам. ID сохраняются текстом; учитываются формат ведущих нулей, счётчики и максимальные существующие номера. Если заголовок поля изменён, предпросмотр покажет «Не найдено»: приведите его к исходному названию. Произвольного редактора сопоставления в этой версии нет.

Повторный импорт неизменённой книги не создаёт дубли. Конфликты с изменёнными данными требуют решения. Если другой сотрудник изменил реестр после предпросмотра, сформируйте предпросмотр заново.

Экспорт создаёт типизированный `.xlsx` со всеми пятью исходными листами, дополнительными листами действий и ссылок на документы. Выбранный экспорт включает соседние постановления общего конверта, чтобы не разрушить связи. Выгрузка содержит вычисленные значения на момент экспорта; для дальнейшей работы импортируйте её в приложение. Файлы документов не встраиваются в Excel — для их переноса используйте резервную копию.

## Хранение и резервные копии

- Размещённая версия: постоянные D1 и R2, привязанные к проекту Sites. Новая публикация кода не заменяет БД и документы. Миграции схемы сохраняются в `drizzle/`.
- Локальная версия: `.wrangler/state`. Не удаляйте эту папку; переносите её целиком при переносе локальной установки. Локальная и размещённая БД независимы.
- «Создать резервную копию» сохраняет JSON с реестром, настройками, счётчиками, действиями, аудитом и содержимым документов; копия также записывается в R2 `backups/`. Скачанный файл храните на отдельном защищённом носителе.
- «Восстановить из копии» после подтверждения заменяет рабочий реестр одной транзакцией БД. До замены создаётся серверный снимок. Файлы загружаются по новым ключам, прежние не удаляются. Права текущих сотрудников сохраняются. Счётчики никогда не уменьшаются.
- Интерфейс поддерживает документ до 10 МБ, совокупные документы резервной копии до 40 МБ, книгу импорта до 15 МБ. Для большего архива администратору развёртывания потребуется согласованный экспорт D1 и объектов R2 средствами хостинга. Автоматического расписания копирования в этой версии нет: назначьте ответственного и выполняйте копии ежедневно и перед массовым импортом.

## Проверки

```powershell
npm test
npx tsc --noEmit
npm run build
```

Тесты используют отдельные временные SQLite-БД. Для проверки оригинальной книги дополнительно задайте `SOURCE_BOOK` абсолютным путём к `.xlsm`. Они не меняют рабочие данные. SQL выполняется через адаптер того же D1-контракта; отдельная проверка развёртывания и HTTP выполняется при выпуске.

## Границы версии

На момент передачи публикация закрытого сайта не выполнена: передача команды публикации в защищённый репозиторий отклонена политикой среды. Локальный сервер успешно проверен через HTTP внутри изолированного процесса; браузер пользователя не смог подключиться к нему из среды Codex. Поэтому визуальная и интерактивная браузерная проверка не подтверждена. Запуск `Запустить.cmd` вручную выполняется в обычной пользовательской среде; это подготовленный способ открыть приложение на данном компьютере.

Нет интеграции с Почтой России, ФССП, банком или email: сотрудники вручную вносят факты. Напоминания отображаются внутри приложения. Остаток долга не вычисляется. Сумма двух этапов никогда не выдаётся как общий приход.

Поиск и пагинация выполняются в браузере после одной серверной загрузки. Это рассчитано на сотни постановлений и тысячи событий, но не на многомиллионные реестры. Импорт зависит от стандартных заголовков исходной книги. Загрузка документов и восстановление ограничены указанными выше размерами. Доступ сотрудников извне дополнительно зависит от политики платформы Sites.

## Основные файлы

`app/WorkspaceApp.tsx` — интерфейс, `app/api/[...path]/route.ts` — защищённые операции сервера, `lib/domain.ts` — правила контроля и финансов, `lib/store.ts` — транзакции, нумерация, импорт и история, `lib/excel.ts` — чтение и экспорт Excel, `db/schema.ts` — реляционная схема, `tests/scenarios.ts` — сценарные проверки.
